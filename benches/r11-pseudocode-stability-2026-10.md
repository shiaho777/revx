# R11 — 跨进程伪代码稳定（2026-10）

同一份 DEX 字节码在两个进程里走出同一段伪代码。不包装 JADX。私有 APK 不入库。

## 原因

join 上每个寄存器一个 phi。这些 phi 以前按 `HashMap<u16, _>` 的迭代顺序调用 `new_value_id`。进程的哈希种子一变，拷贝语句的顺序和 `vN` 编号就变。

语义重命名再按 `HashMap` 顺序做连环替换。`v10 -> v1` 写回去之后，下一轮又会把这个新的 `v1` 收成别的名字。两个进程的替换顺序不同，结果就不同。

## 行为

- phi 按寄存器号升序建立。菱形的 else 臂拷贝是 `v16 = v3` 到 `v21 = v8`，加法是 `v16 + v17`。
- 一行里的原始 token 只替换一次。`v10 = this.v1` 配上 `v1 = this.size` 得到 `v1 = this.size`，不会再变成 `size = this.size`。
- legacy 渲染把落在同一行的标签按块号排序。
- ARM64 四寄存器菱形渲染为 `return x0 + x1`，四个进程文本相同。native phi 的分配顺序没改。

## 未做

普查 schema 仍是 7。区域树回退原因没变。Native SSA 仍用寄存器名集合的迭代顺序分配 phi id；这次的 ARM64 文本里看不到这些 id。
